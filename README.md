# Claude Code и Codex CLI в Docker

Нужны Docker Engine 27.4 или новее, Docker Compose v2 и `make`. Docker скачивает базовые образы и системные пакеты при сборке. CLI устанавливаются из npm через Tinyproxy в домашний каталог контейнера.

## Запуск

Распакуйте комплект вне папки проектов. Тогда её монтирование не откроет агентам `.env` и файлы запуска Compose.

```sh
cp .env.example .env
mkdir -p "$HOME/.config/agent-docker/proxy"
cp allowed-domains.example "$HOME/.config/agent-docker/proxy/allowed-domains"
```

В `.env` укажите в `PROJECTS_DIR` абсолютный путь к существующей папке с проектами. Она будет доступна для записи по пути `/workspace`. На Linux укажите в `AGENT_UID` и `AGENT_GID` значения `id -u` и `id -g` пользователя, которому принадлежат проекты. После первой сборки используйте те же значения UID и GID для доступа к файлам в томе.

В `PROXY_CONFIG_DIR` укажите абсолютный путь к папке с файлом `allowed-domains`. Храните его вне `PROJECTS_DIR`, чтобы он был доступен только сервису `proxy`. Запишите в файл разрешённые домены, по одному на строку. Для разрешения поддоменов используйте форму `*.example.invalid`. Для домена без префикса нужна отдельная запись. Строки с `#` служат комментариями. Пустой список блокирует все внешние назначения.

Для установки CLI добавьте `registry.npmjs.org` в `allowed-domains`. Если контейнер уже работает, примените изменение командой `docker compose restart proxy`.

```sh
make init-claude
make init-codex
docker compose exec agents bash
```

Выберите нужную команду `init-claude` или `init-codex`. `make init` устанавливает оба CLI. Эти команды сами запускают Docker Compose. В уже запущенном комплекте после установки второго CLI первый остаётся доступен.

В открытом Bash перейдите в папку проекта и запустите `claude` или `codex`. Для запуска сразу в папке конкретного проекта используйте `docker compose exec -w /workspace/имя-проекта agents bash`.

## Первый вход

- Claude Code. Выполните `claude`, откройте выведенную ссылку в браузере и вставьте код в терминал, если браузер его покажет. Проверка входа: `claude auth status`.
- Codex. Выполните `codex login --device-auth`. Если вход по коду выключен, включите его в настройках безопасности ChatGPT или обратитесь к администратору рабочего пространства. Проверка входа: `codex login status`.

Домашний каталог `/home/node` хранится в томе `agent-home`. В нём остаются установленные CLI, файлы авторизации, настройки и история. `docker compose restart`, `docker compose up -d --force-recreate` и `docker compose down` сохраняют том. `docker compose down -v` удаляет его вместе с программами и данными входа. Используйте одно имя проекта Compose, чтобы подключать тот же том.

## Сеть и доступ к файлам

Claude Code и Codex работают от обычного пользователя в одном контейнере. Образ подключён только для чтения. Для записи доступны папка проектов, домашний каталог и временные файлы. Оба CLI имеют доступ к одним и тем же смонтированным файлам.

У контейнера с агентами есть только внутренняя сеть Docker. Tinyproxy принимает соединения во внутренней сети, а наружу выходит через отдельную сеть. Все порты сервисов остаются внутри Docker. Папка `PROXY_CONFIG_DIR` монтируется только в сервис `proxy` с правами на чтение. Агентам передаётся внутренний адрес Tinyproxy через `HTTP_PROXY` и `HTTPS_PROXY`. Проверка домена выполняется в Tinyproxy, поэтому изменение этих переменных не меняет список разрешённых адресов. Прокси проверяет имя назначения, указанное клиентом. Разрешайте домены, чьим DNS-ответам вы доверяете.

Если в сети уже есть HTTP-прокси без аутентификации, создайте в `PROXY_CONFIG_DIR` файл `upstream` с одной строкой в формате `host:port`. Адрес должен быть доступен из сети контейнера Tinyproxy. После изменений в `allowed-domains` или `upstream` выполните `docker compose restart proxy`.

На Docker с настройками по умолчанию встроенная песочница Codex может выдать ошибку `bwrap: No permissions to create a new namespace`. В таком случае запустите `codex --sandbox danger-full-access --ask-for-approval on-request` внутри контейнера. В этом режиме изоляцию обеспечивает Docker, а команды Codex могут работать со всеми смонтированными файлами, включая сохранённое состояние CLI.

## Обновление

Для обновления CLI повторите соответствующую команду `make init-claude` или `make init-codex`. По умолчанию npm выбирает тег `latest`. Для установки конкретных версий задайте `AGENT_CLAUDE_CODE_VERSION` и `AGENT_CODEX_VERSION` в `.env`. Базовые образы обновляются отдельно командой `docker compose build --pull --no-cache`, затем `docker compose up -d --wait`.

При переходе с версии комплекта, где оба CLI входили в образ, выполните `make init` или установите нужный CLI отдельно. Используйте прежнее имя проекта Compose и прежние UID и GID, чтобы подключить том с авторизацией.
