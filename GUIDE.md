# Claude Code и Codex CLI в Docker

Комплект состоит из двух сервисов Docker Compose. В `agents` запускаются Claude Code и Codex CLI, в `proxy` работает Tinyproxy. Агенты работают во внутренней сети Docker и выходят наружу через Tinyproxy. Файлы правил доступны только сервису `proxy` и смонтированы в режиме чтения. В окружении агентов виден внутренний адрес Tinyproxy.

## Первый запуск

Понадобятся Docker Engine 27.4 или новее, Docker Compose v2 и `make`. Во время сборки Docker скачивает базовые образы и системные пакеты. Установка CLI проходит через Tinyproxy уже после запуска контейнера.

Распакуйте архив **вне каталога с проектами**. Из распакованной папки выполните:

```sh
cp .env.example .env
mkdir -p "$HOME/.config/agent-docker/proxy"
cp allowed-domains.example "$HOME/.config/agent-docker/proxy/allowed-domains"
id -u
id -g
```

Заполните `.env`:

| Параметр | Значение |
| --- | --- |
| `PROJECTS_DIR` | Абсолютный путь к существующему каталогу проектов. В контейнере это `/workspace`, доступный на запись. |
| `PROXY_CONFIG_DIR` | Абсолютный путь к созданной папке с `allowed-domains`. Держите её вне `PROJECTS_DIR`. |
| `AGENT_UID`, `AGENT_GID` | На Linux подставьте значения `id -u` и `id -g` пользователя, которому принадлежат проекты. |

Добавьте `registry.npmjs.org` в `allowed-domains` и запустите команду для нужного CLI:

```sh
make init-claude
```

```sh
make init-codex
```

Для установки обоих CLI выполните `make init`. Каждая команда автоматически запускает Compose и выводит версию установленного CLI. Чтобы проверить состояние сервисов, выполните:

```sh
docker compose ps
```

В выводе `proxy` должен быть в состоянии `healthy`, а `agents` должен быть запущен.

## Список разрешённых доменов

На хосте откройте файл `allowed-domains` из `PROXY_CONFIG_DIR`. Записывайте одно имя на строку, без схемы, порта и пути. Правило вида `*.example.invalid` разрешает поддомены. Для самого `example.invalid` нужна отдельная строка. Строки с `#` служат комментариями. При пустом списке внешние запросы блокируются.

Начните с доменов выбранного провайдера. Добавляйте адреса Git-сервера и реестров пакетов, если они нужны проекту.

- Для Claude Code с аккаунтом Claude начните с `api.anthropic.com`, `claude.ai`, `claude.com` и `platform.claude.com`. Для SSO и дополнительных функций могут понадобиться другие домены из документации Anthropic.
- Для Codex с входом через ChatGPT начните с `chatgpt.com` и `auth.openai.com`. Если используете вход по API-ключу и стандартный OpenAI API, добавьте `api.openai.com`.
- Страницы входа открываются в браузере хоста. Доступ браузера зависит от сети хоста. Запросы самих CLI проходят через список Tinyproxy.

Чтобы применить правки после запуска:

```sh
docker compose restart proxy
docker compose ps proxy
```

Для существующего вышестоящего HTTP-прокси без аутентификации создайте рядом с `allowed-domains` файл `upstream`. Укажите в нём одну строку в формате `host:port` и перезапустите `proxy`. Этот адрес должен быть доступен из его сети. Tinyproxy применяет список разрешённых доменов и в этом режиме.

## Вход и работа с проектом

Из каталога с `compose.yaml` откройте Bash внутри контейнера. Замените `my-project` на имя папки вашего проекта:

```sh
docker compose exec -w /workspace/my-project agents bash
```

Дальнейшие команды выполняются внутри контейнера:

- **Claude Code.** Выполните `claude`. Откройте ссылку, показанную в терминале, в браузере хоста. Если браузер покажет код, вставьте его обратно в терминал. Проверить вход можно командой `claude auth status`.
- **Codex.** Выполните `codex login --device-auth`, откройте указанную страницу в браузере и введите код. При необходимости включите вход по коду в настройках безопасности ChatGPT или попросите администратора рабочего пространства включить эту возможность. Затем выполните `codex login status` и `codex`.

Если при выполнении команд Codex появляется ошибка `bwrap: No permissions to create a new namespace`, запустите его так:

```sh
codex --sandbox danger-full-access --ask-for-approval on-request
```

В этом режиме границу изоляции задаёт Docker. Команды Codex могут обращаться ко всем доступным контейнеру файлам, включая проекты и общий домашний каталог с состоянием обоих CLI. Все изменения в `/workspace` сразу видны на хосте.

## Перезапуск и обновление

Том `agent-home` хранит домашний каталог контейнера, включая установленные CLI, авторизацию и настройки. По умолчанию Compose создаёт том `agent-docker_agent-home`. Для повторного использования тома сохраняйте имя проекта Compose, а также UID и GID пользователя.

| Операция | Команда из каталога Compose |
| --- | --- |
| Перезапустить сервисы | `docker compose restart` |
| Пересоздать контейнеры с сохранением тома | `docker compose up -d --force-recreate --wait` |
| Остановить и удалить контейнеры с сохранением тома | `docker compose down` |
| Запустить снова | `docker compose up -d --wait` |

Команда `docker compose down -v` удаляет том вместе с установленными CLI, авторизацией, настройками и историей. Файлы проектов хранятся на хосте.

Чтобы обновить CLI, снова запустите `make init-claude` или `make init-codex`. Для установки конкретных версий задайте `AGENT_CLAUDE_CODE_VERSION` и `AGENT_CODEX_VERSION` в `.env` перед вызовом `make`. По умолчанию используется тег `latest`.

При переходе с версии комплекта, где программы входили в образ, выполните `make init` или установите нужный CLI отдельно. Сохраните прежнее имя проекта Compose и UID и GID, чтобы использовать том с авторизацией.

Для обновления базовых образов выполните:

```sh
docker compose build --pull --no-cache
docker compose up -d --wait
```

## Проверка и диагностика

Проверьте версии установленных CLI и журнал прокси:

```sh
docker compose exec -T agents claude --version
docker compose exec -T agents codex --version
docker compose ps
docker compose logs --tail=50 proxy
```

Для диагностики HTTPS укажите в `TEST_HOST` проверяемый домен:

```sh
TEST_HOST=example.invalid
docker compose exec -T agents curl -sS --max-time 15 -o /dev/null \
  -w 'CONNECT %{http_connect}, HTTP %{http_code}\n' "https://$TEST_HOST/"
```

- `CONNECT 200` означает, что прокси разрешил и установил соединение. Если затем указан `HTTP 403`, запрос отклонил сервис назначения или сетевой шлюз после Tinyproxy.
- `CONNECT 403` означает отказ на этапе подключения через прокси. Проверьте точное имя в `allowed-domains` и перезапустите `proxy`.
- Если `proxy` не становится `healthy`, проверьте журнал. Убедитесь, что `PROXY_CONFIG_DIR` существует, а `allowed-domains` доступен сервису на чтение.
- Если проект открывается, но файлы в нём недоступны на запись, сравните UID и GID из `.env` с владельцем каталога на хосте.

На тестовом Docker 27.4 подтвердились фильтрация доменов, отсутствие прямого выхода из контейнера и сохранение тестовых файлов в томе после пересоздания. Вход в реальные аккаунты на тестовом хосте не проверялся.
