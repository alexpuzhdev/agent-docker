# Roadmap agent-docker

Цель проекта - дать пользователю единый терминал Linux для запуска изолированных окружений разработки, работы с Claude Code и Codex и переключения между их сессиями.

## v0.1.0. Базовое окружение

Ветка `release/v0.1.0` содержит MVP на Docker Compose и KVM. Текущий способ работы описан в [руководстве](GUIDE.md).

- `make` или `make vm-setup` с хоста проверяет KVM, ресурсы и доступность прокси, затем готовит гостя Debian и устанавливает Claude Code. Повторная настройка сохраняет диск.
- У каждой VM свой диск, проектные файлы, авторизация и история сессий. Проекты хранятся внутри гостя. На одной Linux-машине можно поднять несколько гостей с отдельными настройками CPU, RAM, диска и прокси.
- Сетевой шлюз расположен вне гостя. Прокси проверяется до установки, исходящие подключения ограничены списком разрешённых доменов. Адрес и учётные данные upstream остаются в конфигурации шлюза, а внутри VM приложения используют обычные HTTP и HTTPS.
- Make позволяет управлять гостями, открывать консоль, запускать Claude Code, входить, выходить и возобновлять сохранённую сессию. `Ctrl+]` отсоединяет терминал, а `make vm-console` подключается обратно к работающему процессу.

На KVM проверены установка через прокси, повторный запуск с тем же диском и возврат к работающей консоли. В пилоте предстоит проверить вход с реальной подпиской и одновременную работу двух VM с разными upstream-прокси. Изоляцию оцениваем по разделению дисков, процессов, сетей и учётных данных гостей. Определение устройства и связывание аккаунтов относятся к политике провайдера.

## Первый выпуск Linux CLI

Пользователь скачивает `agent-docker` и работает из одного полноэкранного терминала. Первый целевой хост - Linux `amd64` с Docker, Compose и доступом к KVM.

- Собрать CLI на Go и публиковать бинарник, контрольную сумму и примечания к выпуску в GitHub Releases. Исходники остаются в этом репозитории. Скрипты и шаблоны поставляются вместе с приложением, чтобы его можно было запустить из любого каталога.
- Переиспользовать текущие Make-цели и скрипты. Добавить проверку зависимостей, создание VM, выбор ресурсов и ручного прокси, список, запуск и остановку VM.
- Показать в меню окружения и открывать родную консоль агента внутри приложения. Сценарий первого выпуска - создать гостя, открыть Claude Code, вернуться в меню, выбрать другую VM и подключиться обратно к первой. На этом этапе достаточно одного открытого терминала на VM.
- Добавить установку и запуск Codex в госте с сохранением ограничений на исходящую сеть.

## Сессии и панель статуса

- Хранить привязку сессии к VM, агенту и проекту. Открытые сессии подключать к живому процессу, сохранённые возобновлять по ID. После выключения VM живой процесс завершается, а сохранённая история остаётся на диске.
- Для нескольких живых сессий в одной VM выделять каждой свой псевдотерминал. Проверить переключение, передачу клавиш, изменение размеров окна и восстановление после переподключения.
- В панели показывать VM, проект, имя сессии, агент, версию, модель, состояние авторизации и, когда доступны, тариф, долю остатка лимита и время сброса. Отмечать время последнего обновления или отсутствие данных. Лимиты относятся к аккаунту или провайдеру, через которого работает агент.
- Для Claude Code брать модель, сессию и доступные лимиты из `statusline`, состояние входа - из `claude auth status`. Автоматическое определение тарифа зависит от доступных данных. Вход пользователь проходит в штатном CLI внутри гостя.
- Для Codex использовать официальный App Server для списка и восстановления сессий, а также данных о модели, тарифе и лимитах там, где их возвращает выбранный способ авторизации. Передавать в панель только поля для отображения. Учётные данные остаются внутри гостя.

## Git-шлюз

- Вынести шлюз и токены проектов за пределы VM. Пользователь назначает репозитории выбранному окружению. Гость получает рабочую копию и адрес шлюза, а также видит данные и историю выданного репозитория.
- `status`, `diff` и `commit` выполняются локально. `clone`, `fetch` и `push` идут через шлюз. Личные учётные данные и настройки Git пользователя остаются за пределами гостя.
- Начать с одного Git-провайдера. Шлюз проверяет, какой VM разрешён доступ к репозиторию. По умолчанию выдаётся чтение, запись включается отдельно. На пилоте проверить запрет доступа к чужому репозиторию и запрет записи без разрешения.

## Интеграция с провайдером прокси

- Оставить ручную настройку. Опционально добавить подключение API провайдера и выбор прокси для конкретной VM из списка в приложении.
- Хранить ключ API вне гостя. Проверять новый прокси перед сменой. Если проверка не прошла, сохранять действующую конфигурацию.
- Проверить две VM с разными upstream и подтвердить фактический внешний IP каждой. При недоступном прокси и обращении к запрещённому адресу проверять отказ без прямого выхода в интернет.

## Пилот и критерии 1.0.0

- Заказчик устанавливает CLI по инструкции на Linux-хост и выполняет весь рабочий сценарий в одном терминале. Во время пилота предоставляем полный функционал для оценки.
- Проверены создание двух гостей, работа с Claude Code и Codex, переключение между VM и сессиями, переподключение, перезапуск с сохранением проектов и авторизации.
- Проверены политика исходящего доступа, отдельные прокси и права Git-шлюза. Интеграция с API прокси опциональна. Ручной настройки достаточно для релиза.
- Опубликованы бинарник, контрольная сумма и руководство по установке, обновлению и сохранению данных.

## После 1.0.0. Монетизация

Решение о платных возможностях и цене принимаем после пилота. Проверяем, какие функции заказчик использует регулярно и за какие готов платить.

- Основная гипотеза - бесплатная локальная версия с одной VM, одним выбранным агентом, сохранением сессий и ручной настройкой прокси. Подписка даёт управление несколькими VM и живыми сессиями, Git-шлюз и интеграцию с API прокси.
- Альтернатива - полный доступ на пробный период с подпиской для продолжения работы.
- Подписка покрывает продукт для управления окружениями. Claude Code и Codex работают с аккаунтом пользователя и его тарифом. Если локальное ядро остаётся открытым, платные возможности можно поставлять как отдельное дополнение или сервис.
